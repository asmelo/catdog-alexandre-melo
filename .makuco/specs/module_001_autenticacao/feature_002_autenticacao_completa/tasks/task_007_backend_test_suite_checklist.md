## Notes

- **DESVIO-055 — `tsconfig.test.json` criado (arquivo fora da tabela *Files*), e o `tsconfig.json` ajustado.** A tabela manda **três** `.spec.ts` dentro de `src/`, e o `tsconfig.json` tinha `include: ["src/**/*.ts"]` sem `exclude` de spec. A consequência era dupla e ambas foram **reproduzidas** antes da correção: (a) `npm run build` passaria a emitir `dist/**/*.spec.js` — arquivo de teste no pacote de produção, carregando `@types/jest` e os dublês; (b) `npm run typecheck` (`tsc --noEmit`) não vê `describe`/`it`/`expect`, que são globais de `@types/jest`, e acusaria erro em cada spec. Três saídas foram consideradas: mover os specs para `tests/` (sairia da tabela *Files*, que este projeto respeitou em todos os slices); acrescentar `types: ["node","jest"]` ao `tsconfig.json` de produção (faria o build de produção depender de tipos de teste e **não** resolveria o (a)); ou **excluir os specs do projeto de build e criar um projeto próprio para eles**, que é o padrão que o `tsconfig.seed.json` já estabeleceu na task 001 para o que vive fora de `src/`. Escolhida a terceira. Resultado **medido**: build sem nenhum spec em `dist/`, `typecheck` com 0 erros nos três projetos, e os specs type-checked **duas** vezes (no `typecheck` e na própria execução, porque o `ts-jest` usa esse mesmo `tsconfig.test.json`) com as mesmas flags estritas do código de produção.
- **DECISÃO-056 — `tsconfig.json` foi modificado, e isso não viola a AC #9.** A AC diz "nenhum arquivo de `src/` foi alterado"; o `tsconfig.json` está na raiz do serviço, não em `src/`. A mudança é de **duas** linhas efetivas (um item no `exclude`) e é a única forma de o (a) do DESVIO-055 não acontecer, já que é este arquivo que o `npm run build` usa. Nenhum arquivo pré-existente de `src/` foi tocado — confirmado por `git diff --stat`.
